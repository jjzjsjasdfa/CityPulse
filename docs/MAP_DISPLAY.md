# 活动地图分级展示

手机与网页共用 `mobile/src/map/presentation.ts` 的规则。原生端使用现有
`react-native-maps`；网页使用 Leaflet 与 OpenStreetMap 底图。地图页无顶部标题框或档位选项。
触屏通过双指缩放；非触屏网页保留加减按钮，也支持鼠标滚轮。

## 颜色与大小

八个现有活动类别沿用统一颜色字典 `mobile/src/theme.ts`，圆点与类别、名称文字同色。
色值已调深，使 12 号文字在浅色标签上清晰可读。

| 时效 | 圆点直径（React Native 布局单位 / 网页 CSS px） |
| --- | --- |
| 正在发生：开始时间 ≤ 当前时间 < 结束时间 | 30 |
| 尚未开始，3 天内 | 26 |
| 3 天以上、7 天内 | 22 |
| 7 天以上、15 天内 | 18 |
| 15 天以上、30 天内 | 15 |
| 30 天以上 | 12 |

一个月暂按连续 30 天计算，边界包含第 3、7、15、30 天。日期统一按时间戳比较，
不受手机时区影响。每 30 秒及应用回到前台时更新大小。
普通视图隐藏已结束活动；远景保留已收藏的历史活动。结束、取消、延期和异常日期均使用最小圆点，
不会误标为正在进行。

网页只让可见圆点和文字标签响应点击，透明布局区域穿透到地图；校验手指原始坐标，
避免浏览器将空白处的轻触归到附近标签，拖动不打开详情。名称使用 12 号字、16 行高，
标签宽度不超过屏幕的 38%，且最多 144；最多三行。普通名称完整展示，
超长名称末尾省略，点击打开详情读取全称，读屏标签也包含全称。系统字号可放大到 1.15 倍。

## 地图层级

按可见区域横向地面距离判断，适配不同屏幕和纬度，避免硬编码某家地图的 zoom 数值。
“省域”和“城市”表示近似尺度，不按行政边界切换。

| 横向范围 | 展示内容 |
| --- | --- |
| 达到 40 km | 仅当前范围的收藏圆点，不请求普通活动地图接口 |
| 11–40 km | 范围内所有活动的彩色圆点 |
| 2.5–11 km | 圆点 + 同色活动类别 |
| 不超过 2.5 km | 圆点 + 同色活动名称 |

经度跨度超过 20°或纬度跨度超过 30°也进入远景，以保证查询范围受控。
这些是数据层级边界，视觉在边界附近连续交叉淡入淡出：名称在横向 2–3 km 内过渡，
类别在 9–13 km 内过渡，非收藏圆点在 30–40 km 内淡出。
反向缩放从当前动画状态继续，标记锚点固定，文字有轻微位移过渡。
密集区域保留所有圆点，放不下的标签渐隐；继续放大后显示更多名称，点击圆点始终可查看全称。
移动和缩放时保留上一批成功数据，避免等待新接口时整层闪空。
原生 iOS 使用地图自带比例尺；Android 和网页显示实时换算的 100 单位比例尺，
数字随手势更新，不采用离散档位的固定显示。
地图独立展示全部类别，不受信息流类别筛选限制；远景仍只展示收藏标记。
跨越日期变更线的近景拆成两个合法视口查询。所有标记均再次在客户端做视口裁剪。

## 加载与收藏

- 地图移动停止 300 ms 后开始查询；继续移动、退出地图或进入远景时取消旧请求和剩余分页。
- 不固定城市，查询当前视口内的已发布活动。接口仍接受可选 `city`。
- 每页最多 500 点，客户端持续分页、逐批显示，避免原来的 500 点截断。
- 首次请求失败时显示明确标识的离线演示；后续页失败保留已加载的真实数据并提示未加载完整。
- 收藏保存 ID 及活动快照（含经纬度和结束时间）；旧版仅有 ID 的收藏以最多四个并发详情请求恢复。
  网络不可用且从未缓存坐标的旧收藏，需要联网成功一次后才能定位。
- 原生自定义标记只在内容改变时短暂刷新，随后关闭持续截图跟踪。

## 接口变化

`GET /api/v1/events/map` 新增 `offset`、`limit`；`city` 改为可选。
`MapEvent` 新增必需的 `ends_at`；返回 `meta.count`、`meta.has_next`、`meta.next_offset`。
结束时间本来就在数据库中，本次无需数据库迁移。

必须同时更新后端、`mobile/openapi.json` 和生成的 `mobile/src/api/schema.d.ts`。
客户端使用旧版后端时无法可靠判断活动结束时间。

定位、默认 500 米比例尺和附近新活动的八方向提示见
[LOCATION_GUIDANCE.md](LOCATION_GUIDANCE.md)。

## 验证

在 `backend/`：

```powershell
uv sync --all-extras
uv run pytest
uv run ruff check app tests
```

后端测试使用模拟会话验证空间查询、可选城市、分页和结束时间契约，不需要修改本机数据库。
实际 PostGIS 执行和数据密集情况下的性能仍需在部署环境验证。

在 `mobile/`：

```powershell
npm run typecheck
npm run test:map
npx expo export --platform web
npm run preview:map
```

临时数据和真实手势集成测试见 [DEMO_DATA.md](DEMO_DATA.md)。
运行 `npm run smoke:demo`，默认连接 `http://localhost:18081` 和本地测试接口，
可用 `CHROME_PATH`、`PREVIEW_URL` 覆盖。截图写入忽略的 `mobile/artifacts/`。

覆盖：六档大小、边界时刻、四层缩放、超过 500 点的分页、迟到请求取消、收藏重启恢复、
时间自动更新、320/390 px 标签尺寸和离线提示。

真机还应在 Expo Go 上检查双指缩放、自定义标记点击和 Android/iOS 的原生标记布局。
网页截图验证的是共享展示规则与文字尺寸，不代替原生设备验证。
