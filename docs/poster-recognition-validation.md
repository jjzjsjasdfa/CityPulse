# 海报识别验证与已知限制

2026-09-17：用本地 14 张用户提供的海报验证。图片不进 Git，文件名只用于报告标记，不作为日期、城市、艺人或标题的识别依据。测试过程不把这些海报自动发布到正式数据库。

## 当前处理流程

1. 登录后上传图片；后端校验身份、格式、大小和所有权。
2. 独立 PaddleOCR 服务使用 PP-OCRv5 server 检测与识别模型，保留坐标与置信分数。修正 EXIF 朝向，对最多四处不清晰文字作局部增强重识别。仅在分数提高时替换；分数不等于事实正确率。
3. 根据文字框位置关联标签、同行日期及场馆，拆分多城市巡演；支持月日、日期区间、独立时钟。看不到年份时不凭文件名补年份。
4. 从明确阵容或演出上下文抽取人物；音乐会曲目、作者、导演以及金曲致敬海报的原唱不会默认成为出席艺人。
5. 用已核实词条的名称、别名辅助纠错。长名称且唯一高相似度可替换并标明来源；短姓名、同名或接近候选保留歧义供查看和审核。原始证据不被覆盖。
6. 标题、具体场馆、完整日期共同确认且仅有一个对应活动时自动收藏。缺年份、多场次、地点不明确或存在重要疑点时让用户确认，不任意选择一场。
7. 未入库资料待管理员审核；管理员可查看原图、原文、候选词条并编辑模板、建立词条、合并已有活动或创建活动。普通用户的 API 响应不包含原始 OCR 或文字框数据。
8. 结果与分享文案均包含“识别内容可能不准确，请以官方公告为准。”外部参考链接来自已存储的词条或活动官方来源，没有资料时不生成虚假链接。

## 同事复现

先按仓库说明启动 Docker 后端与前端。依赖和模型版本沿用仓库锁定文件，模型存在 Docker 缓存卷，不上传 Git。

在 `mobile` 目录运行（可用 `DOCKER_PATH` 指定 Docker 可执行文件）：

```powershell
node scripts/evaluate-posters.mjs "本机海报目录" artifacts/poster-corpus.json
```

在有后端依赖的 Python 环境中，从 `backend` 目录回放结构化提取，无需重复 OCR：

```powershell
python scripts/evaluate_poster_text.py ../mobile/artifacts/poster-corpus.json ../mobile/artifacts/poster-facts.json
```

`mobile/artifacts` 已忽略；报告含用户图片识别内容，不应提交。通用回归断言位于 `backend/tests/test_posters.py`，权限与数据库集成断言位于 `test_poster_api.py`、`test_knowledge.py`。浏览器验证脚本 `mobile/scripts/smoke-knowledge.mjs` 使用临时账号并清理自己的测试记录。
