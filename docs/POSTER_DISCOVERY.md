# 海报识别与歌手资料

发现页的“上传活动海报”支持网页和 Expo 手机端。用户登录后上传，Docker 默认使用独立的 PaddleOCR 服务在本机识别，图片不会发送到第三方识别服务。详见 [飞桨部署说明](PADDLE_OCR.md)。本机 uvicorn 未配置 `POSTER_OCR_URL` 时使用 Tesseract，需要安装 Tesseract 和中文语言包，并安装 pyproject.toml 中的 Pillow。

上传支持 JPEG/PNG/WebP，限制 8 MB、1600 万像素。图片去除元数据后以 PNG 保存到数据库，仅投稿人可查看识别记录，管理员可查看原图。飞桨单任务推理，后端等待上限 180 秒，繁忙时提示重试；Tesseract 超时 45 秒。同一用户重复上传相同文件复用识别记录，识别版本升级时会重识别待审核记录。此版本未实现自动清理原图，正式部署前应制定保存期限和容量配额。

固定模板字段均来自 OCR 原文；没有依据的字段留空，不推断年份、主办方或艺人荣誉。当前采用标签/行规则提取，复杂设计、竖排及艺术字可能识别不全。歌手姓名与别名精确匹配档案；资料库初始为空，管理员在“审核 → 海报与歌手资料 → 歌手资料库”维护有来源的真实资料。同名歌手可以有不同档案，需要用户核对，不能仅凭姓名推断身份。年龄根据出生日期计算。

地图匹配使用名称与地点；只有名称一致、具体场馆一致、完整日期一致且候选唯一才自动收藏。同名多场次或缺日期只展示候选，用户选择。收藏沿用当前应用的用户本机存储，未改为跨设备同步。新活动匹配最多检查 2000 条有效已发布活动，歌手关联最多检查 5000 个档案；规模扩大后需要数据库搜索索引和分页匹配。

投稿先进入独立审核队列。管理员可拒绝，或关联已有已发布活动（追加阵容及参考链接，不覆盖原字段），或填写完整地点坐标、日期、来源等字段后创建新音乐节。审核时关联歌手档案，缺失档案先维护再关联。原始图片、文字、投稿人、审核人和结论保留在数据库中。活动详情通过 `/events/{id}/background` 展示已核实阵容及参考链接。

分享目前输出可复制的活动介绍文字，未上线公开海报分享页或应用商店下载链接。

验证：`npm run typecheck`；后端 `pytest tests/test_posters.py`；设置 `CITYPULSE_TEST_POSTGRES=1` 后运行 `tests/test_poster_api.py`（独立事务测试 schema，不写入正式记录）。
