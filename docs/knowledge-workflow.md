# 海报发现与统一词条

## 用户流程

发现页上传海报 → PaddleOCR → 活动模板（名称、阵容、主办方、时间、地点）。
只有图片可提取的内容才进入原始模板；未知值留空。点击名称可以打开已核实词条，
无法唯一匹配的名称打开检索，避免把同名人物误认为同一人。

候选活动使用名称和场地信息匹配。活动名、具体场馆、日期完全一致且只有一个候选时，
上传接口将活动加入当前账号收藏。相似但不确定的结果交给用户核对场次。
“模糊搜索更多活动”支持活动名、场馆及城市筛选和分页。

## 词条

`entries` 统一保存人物、机构、品牌、地点和活动；`entry_names` 保存规范化名称和别名，
使用 PostgreSQL pg_trgm 索引查询相似名称。人物保留出生日期、性别、籍贯、别名、
粉丝称谓、应援色、经纪公司、荣誉、代表作和参考链接；年龄在显示时计算。
迁移将旧歌手档案复制为同 UUID 的人物词条，旧 Artist API 继续兼容。

管理员在审核页的“词条库”中检索、新建或修改词条。修改必须携带读取时的 version，
旧版本提交返回 409，避免覆盖其他人的修改。统一词条接口记录修改前后快照和审核人。
参考链接只接受 HTTP/HTTPS；界面将其标记为外部跳转。

## 投稿审批

图片和 OCR 原文保持不变。管理员可以填写核实后的模板，关联已有活动或创建活动，
关联已有词条，或填写与本投稿一起入库的新词条。

批准时在单一数据库事务内保存活动、词条、角色关联、参考链接、修改记录和投稿状态，
并收藏至投稿账号。失败全部回滚，重复处理返回 409。拒绝不会公开词条。
合并到已有活动仅补充背景关系，不覆盖现有时间、地点等主字段；主字段调整使用原活动审核编辑页。
未知信息仍需要人工核实，不能因为海报上出现了姓名就自动补全人物生平。

## 收藏

`favorites` 以 user_id/event_id 为组合主键，重复收藏幂等；读写只能操作登录账号自身。
正式模式从服务端同步，首次启动迁移当前账号旧的本机收藏。调试模式仍使用独立本机数据。
切换“我的”会刷新服务端收藏，以显示后台审核确认的活动。

## 部署与验证

正常 `docker compose up --build` 即可运行 Alembic 新迁移 20260917_0009。
PostgreSQL 需允许应用迁移用户创建 pg_trgm 扩展；受限托管数据库由管理员预先创建。
迁移新增表和索引，保留已有用户、海报、歌手和活动。无需提交模型缓存、账号数据或本地 .env。

`CITYPULSE_TEST_POSTGRES=1 python -m pytest` 包含词条别名/模糊检索、重名歧义、版本冲突、
权限、审批事务回滚、重复审批、收藏幂等及账号隔离测试。测试使用独立回滚 schema。
